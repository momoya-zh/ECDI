## §3 关键决策点（含倾向）

### D1 原语形态：描边弧 vs 楔形（pie）vs 整环

- 候选：① **描边弧**（有宽度的一段弧）② 楔形/扇形（实心到圆心）③ 整环（固定整圆）
- **倾向 ①**：`REQ-08` 的三个消费者形态——环形进度（弧）/ spinner（弧）/ 仪表盘（弧）——**全部是弧**；
  楔形与整环都可由弧组合或退化表达（整环 = sweep 360° 的描边弧；楔形**不**由本原语负责）。
- ★ 理由（条 95①「一个概念只用一个词」）：**不引入 `DrawPie` / `DrawRing` 第二个名字**——将来真有楔形消费者再另立。

### D2 角度单位与起点方向

- 候选：① **度**（0–360）② 弧度（0–2π）
- **倾向 ① 度**：教学框架（条 95「Everyone Can Do It」）——`SetProgress(0.75f)` → 扫过 270° 这类心智模型无需换算。
- **起点方向倾向「3 点钟 = 0°，顺时针为正」**：与 GDI `AngleArc` / 屏幕坐标 y 向下的惯例一致，后端**零转换**。
- ★★ **v1.1 订正（评审 §1-①）**：v1.0 在此写「`sweep` 可负 ⇒ 逆时针」，却在 R1 用**升序区间** `[a0, a0+sweep]` 描述区域 ⇒ **负 sweep 时下界大于上界**，按普通区间语义是空集，与「逆时针」自相矛盾。**现行语义见 §3.5 C33-2**：`sweep` 是**有向扫角**，落在弧内与否**按符号判定，不得写成升序区间**。
- **环形进度条的起点**（12 点钟）由**控件层**折算（控件传 `startAngle = 270`），**不进原语契约**——原语保持中立（条 23：论证用契约语言，不把单个消费者的偏好写进公共层）。

### D3 线宽语义与退化输入

- **倾向**：`width` 与 `DrawLine` 同语义（框架层 float、后端 `lround` + 下限 1px）；`sweep == 0` ⇒ **不画**（与 `DrawLine` 的零长线退化一致）；
  `radius <= 0` ⇒ 不画。★ **不留「宽度 0 = 实心弧」的后门**（那会引入第二个语义）。
- ★★ **v1.1 补全（评审 §2）**：v1.0 只覆盖了以上三例，**漏了 `radius <= width/2`（内半径非正）、NaN / ±Inf、极大半径/线宽**。完整退化表见 **§3.5 C33-4**。
- ★★ **`radius <= width/2` 的特殊性（本稿自查发现，评审未点出）**：此时半宽被**钳制**为 `hw = min(width/2, radius)` ⇒ 几何上**必然退化成扇形（实心圆盘）**，而扇形正是 **D1 明确排除**的形态。⇒ 契约必须**明写「此输入下退化为扇形」**（用户 2026-10-14 拍板取钳制 + 明写），否则 `DrawArc` 会在某输入下**静默变成 D1 排除的东西**。
  ★ **与 D3 原句不冲突的辨析**：D3 反对的是把 `width = 0` 当**实心弧的语义后门**（用户主动用 0 表达「我要实心」）；而 `radius <= width/2` 是**输入钳制的几何后果**（用户没想画扇形，是几何使然）。两者性质不同，契约里分开写。

### D4 AA 模型

- 候选：① **圆弧 stadium 带覆盖度** ② 解析覆盖度 ③ SDF
- **采纳 ①**：与 `LineCoverage` 直系同族（条 97、K19）——「点到**线段**距离 ≤ hw」换成「点到**弧中心线**距离 ≤ hw」（§3.5 C33-1），**同一套超采样 + 同一张输出网格 + 同一个 `RasterizeMask`**。
- ★★ **v1.1 措辞订正（评审 §1-②）**：v1.0 用「stadium 带」而 R1 用径向截断描述 ⇒ **两者互斥**（stadium 在 `LineCoverage` 里两端是**半圆盘** = 圆帽，K19；R1 的区间写法是**平头**）。用户 2026-10-14 拍板取 **②圆帽端点** ⇒ **D4 的「stadium」措辞是对的，R1 的区间写法才是错的那一方**，故 R1 已按「到弧中心线距离 ≤ hw」改写。
- ★ **圆帽带来的一个便利（值得写进初设）**：该定义是**单一式子**，**自动覆盖整圆**——`|sweep| = 360°` 时弧中心线退化为整圆，「到中心线距离」= `|dist(p,c) − r|` ⇒ 自然得到圆环，**无需为接缝写特例**（§3.5 C33-3）。★ 但**解析面积参照必须特例**：整圆时两侧半圆帽首尾重合，`面积 = sweep·r·w` 会**多算**一个圆帽面积（§3.5 C33-5）。
- ★ 选①不选②的理由同 Phase 8.6 D3：解析法要为「圆环扇形 × 像素方格」单独推面积公式，而超采样对任何形状同一套代码；
  选①不选③的理由：覆盖度需要**面积正确**（R8 的面积守恒断言），SDF 不保证。

### D5 虚函数形态：纯虚 vs 默认空实现 ★（本 Phase 唯一涉及「破坏面」的决策）

- **已裁决（用户 2026-10-14）：① 纯虚。**
- ★ 两条路的代价都必须写明：
  - **① 纯虚**：进穷尽集 ⇒ 库内 3 个实现者 + **库外第 4 个实现者 `PaintProbe`** 都必须加 override，否则**编译失败**
    （条 104「想保持可选就不能进穷尽集」的反面——本项目选择**最强契约**）；好处 = **无静默失效**。
  - **② 默认空实现**：零破坏（Phase 32 S7 先例：`SetBackdropSurface` 带默认实现 ⇒ 7 个实现者零改动）；
    代价 = 条 104 的「半可选 / 静默失效」——库外后端忘了实现 ⇒ 环 silently 不画，无从诊断。
- ★★ **v1.1 补记（评审 §3）**：纯虚的破坏面**不止库内三个实现者**——**凡从 `RenderingBackend` 派生的库外实现都可能无法原样编译**。故 R7 已拆两面、`PaintProbe` 已升为**交付项 R9**（含转发参数/计数/计时三项验证），不再只写在风险里。
- ★ **本项目既有裁决先例**：Phase 12 曾因「加 7 个纯虚需同步 2 个测试替身」被记为**代价**；Phase 32 反过来因「默认实现换来零改动」被记为**收益**。
  ⇒ 两条路都有落款，选哪条都要写明代价，不许只说好处。

### D6 `RingProgressBar` 的继承与命名

- **已裁决（用户 2026-10-14）**：`RingProgressBar : public Widget`（**不**继承 `ProgressBar`——那个的 `OnPaint` 是水平语义，K14）；
  命名 `RingProgressBar`（与既有 `ProgressBar` 同族同词，条 95①「一个概念只用一个词」）。
- ★ **YAGNI 边界如实写明**：当前唯一真实消费者是 harness（K16 证明 harness 也能自己拼）⇒ 框架侧做控件属于
  **「为第一个真实消费者开能力」**（用户 2026-10-14 明确选择，见 §6），**不是**投机抽象；
  **不得**为此先把 `ProgressBar` 的值/动画/主题三件抽成共享基类（条 22：第二个消费者出现才抽）。
- ★★ **v1.1 补全（评审 §6）**：控件的**最小行为**须冻结为契约（进度范围/NaN · 动画重入语义 · 尺寸策略 · 样式字段 · 线宽过大退化 · 禁用/隐藏时动画令牌），见 **§3.5 C33-10**。评审赞同「**暂不开放 `SetStartAngle`**」（D7）——理由同 YAGNI。

### D7 起点：控件层的默认朝向

- **倾向**：`RingProgressBar` 默认从 **12 点钟起、顺时针**（进度条惯例：0% 在正上方，100% 回到正上方）；
  实现 = 控件传 `startAngle = 270°`（3 点钟制）。★ 是否开放 `SetStartAngle` **留初设**（YAGNI：无第二个消费者不开放）。

## §3.5 公共契约草案（★ v1.1 新增——评审「最希望补齐的三件事」之第 1 件）

> 本节只冻结**可判语义**；实现形态（采样密度/缓存布局/缓冲尺寸/后端资源）留详设。

| # | 契约 | 内容 |
|---|---|---|
| **C33-1** | **几何定义（唯一式子）** | `DrawArc(center, radius, startAngle, sweepAngle, width, color)` 的绘制区域 = **到「弧中心线」的距离 ≤ hw** 的点集。**弧中心线** = 以 `center` 为心、`radius` 为半径、从 `startAngle` 起按 `sweepAngle` **有向**扫过的圆弧（**含两端点**）。`hw = min(width, 2·radius) / 2`（钳制见 C33-4）。★ 圆帽端点 = 该定义的直接后果（线段两端点在中心线上 ⇒ 两端自然形成半径 `hw` 的半圆盘），**不是额外特性** |
| **C33-2** | **角度与有向扫角** | 单位 = **度**；`0°` = **3 点钟方向**；**正 = 顺时针**（屏幕坐标 y 向下）。`sweepAngle` **带符号**：`> 0` 顺时针、`< 0` 逆时针。★ **落在弧内的判定按符号进行，禁止写成升序区间 `[a0, a0+sweep]`**（负 sweep 下该区间为空——v1.0 的矛盾点）。角度**不要求**调用方归一化：`startAngle` 取任意实数（内部按 `mod 360` 解释） |
| **C33-3** | **整圆与跨 0°** | ① `startAngle = 350°, sweep = 20°` ⇒ 画**跨越 0° 的 20° 弧**（不得因跨越而截断）；② `\|sweep\| = 360°` ⇒ **完整圆环**（C33-1 的单一式子自然给出，接缝**不重不漏**——由「距离 ≤ hw」的连续性保证，非靠特判拼合）；③ `sweep = -360°` ⇒ **同样是完整圆环**（方向对整圆无观感差异，语义上仍按逆时针，实现可等价处理） |
| **C33-4** | **退化与钳制表（★ 全部为公共契约，不得由后端各自决定）** | `radius <= 0` ⇒ **不画**（拒绝，不取绝对值——不静默改变输入语义）· `width <= 0` ⇒ **不画**（沿 `DrawLine` 家族，K22）· `sweep == 0` ⇒ **不画** · **`radius <= width/2` ⇒ `hw` 钳制为 `radius`，几何退化为扇形（实心圆盘）**——★ **明写为已知语义**（D3 辨析：这是钳制的几何后果，不是「宽度 0 = 实心」的后门）· **`\|sweep\| > 360°` ⇒ 钳制到 `±360°`**（沿全库钳制家族 K22；多圈扫角无观感意义且会引入重复覆盖）· **NaN / ±Inf（任一浮点入参）⇒ 不画**（不进入归一化/取整路径，杜绝 UB）· **极大 `radius`/`width` ⇒ 几何网格超出安全尺寸时不画 + 一次 Warning**（沿 Phase 24 `PatchSurface` 的 2M 像素 one-shot 告警先例） |
| **C33-5** | **面积参照（测试用，非 API）** | 解析面积 = `\|sweep\|·r·hw·2`（弧段）+ **两端圆帽**（各 `π·hw²/2`，合一个整圆 `π·hw²`）。★ **整圆时（`\|sweep\| = 360°`）弧段本身已闭合，圆帽不再追加**（否则多算 `π·hw²`）⇒ 参照式**必须按 `\|sweep\| < 360°` / `= 360°` 分段** |
| **C33-6** | **后端几何一致性** | GDI 与 GL **可以有不同的实现机制**（`PatchSurface` vs 图集槽位），**不得有不同的几何语义**：角度单位/方向、端点样式、宽度取整、退化与钳制行为**全部以上表为准** |
| **C33-7** | **GL 图集满降级（修订 R4）** | 降级**必须仍画弧**——**禁止**照搬 `DrawLine` 的 `SolidSegment`（K18：那是**直线段**四边形，会把弧降级成直线）。候选 = ① 以弧的**弦**做扇形逼近（多段 `SolidSegment`，段数固定小常量）② 无 AA 的硬边弧（覆盖度二值化后走同一 `TexturedQuad`）——**由初设择一**，但「仍是弧」是契约 |
| **C33-8** | **GDI 补丁边界** | 覆盖度网格的 bbox 必须**含抗锯齿外扩**（= `hw` 向上取整 + 1px 安全边），沿 `LineCoverage` 的 `originX/originY`「单点出参」先例（生成器算一次、随网格携带，调用方零重算） |
| **C33-9** | **记录后端的参数语义** | `RecordingBackend` 记录**调用方原样传入的参数**（**不做归一化/钳制**）——凡归一化、钳制、取整一律在**执行端**发生。★ 理由：记录件是**测试观测缝**，若它悄悄改参数，「断言原样转发」就失去意义（K21 同族） |
| **C33-10** | ★ **`RingProgressBar` 最小行为** | ① **进度范围 = `[0,1]` 钳制**（沿 `ProgressBar::SetProgress` 先例）、**NaN ⇒ 不改变当前值且不启动动画**（拒绝，不产生未定义状态）；② **动画重入 = 从当前呈现值重新过渡**（沿 `ProgressBar::AnimateTo` 的「替换式重启」先例，K15）；③ **尺寸策略 = 用 `min(width,height)` 作为直径**、圆心居中（宽高不等时不拉伸、不报错）；④ **样式字段 = 轨道色 / 进度色 / 线宽**（不放内外边距——无消费者）；⑤ **线宽过大 ⇒ 沿 C33-4 钳制**（线与半径关系同上）；⑥ **禁用/隐藏/脱树 ⇒ 动画令牌随 `AnimationToken` RAII 自动标脏**（沿 `ProgressBar` 既有形态，不新造机制） |
