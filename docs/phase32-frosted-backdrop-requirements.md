## §1 动机

### 1.1 用户需求原话（2026-10-09）

> 「整体的雾面效果，也就是整个程序的底部是雾面的，包括标题栏，**控件是正常的不透明样式**」
> 「整框统一雾面，透明度 0.8f，兼容，半透明白色，要做」
> 「圆角用系统圆角即可，浮层雾面可以接受，我们只需要位置、图标是清晰的即可」

**拆成可判的四条**：

| # | 要求 | 说明 |
|---|---|---|
| **R-a** | **整窗**雾面 | 含标题栏在内，整个窗口底面统一材质（不是局部区域） |
| **R-b** | **控件不透明** | 文字 / 图标 / 按钮照常清晰绘制，不受雾面影响。★ **v1.1 增测的可落地条件（K13）**：**控件像素必须携带 `alpha = 255`** —— 否则 DWM 会把「alpha=0 的窗口内容」与材质一起混合，**连控件也被冲淡**（实测误差 47.8；补 alpha 后误差 **0.00**） |
| **R-c** | **降级到半透明白不透明度 0.8** | ★ **术语钉死**：`Color::a` 的语义是**不透明度**（`a = 1.0` = 完全不透明，见 `Color.h:19`）；故此处 = **不透明度 0.8**（= alpha 字节 204），**不是**「透明度 0.8」（那将是 80% 透明）。用户原话的「透明度 0.8f」按 §1.1 语境与实测配置（`probe3.cpp:30` `bgA = 204; // 0.8*255`）解释为不透明度 0.8。**系统不支持材质时退化为它，不是裸透**（见 §2 K4）。★ **v1.1 已定形态（K14/P4）**：**预乘白 0.8 的 DIB + `AlphaBlend` 提交 + 控件 alpha 255** —— 底衬仍透出（真半透明白），控件精确不透明，**不需要分层窗**。★ **用户 2026-10-11 拍板**：「**降级不模糊能接受**」 |
| **R-d** | **用系统圆角** | 圆角沿用既有 Phase 12 的 `DWMWCP_ROUND`，本 Phase 不新增自绘圆角 |

### K3 ★ 清屏通道**无 alpha 语义**（实测，本 Phase 必须解决）

`GDIBackend::BeginFrame`（`:251-277`）用 `CreateSolidBrush` + `FillRect` 清屏，源码自注（`:269`）：

> 「决策 21/23：`ToColorRef` 内含 `ToByte` Clamp；★ **alpha 被忽略（`COLORREF` 无 alpha 通道）**」

**事实（源码级）**：`ToColorRef` 丢弃 alpha ⇒ **应用无法通过背景色表达「留空」**。这是本 Phase 唯一需要触及的既有渲染路径。

★ **K3 的结论强度已按探针 6 修正（v1.1 的核心修订）**：v1.0 在此写「**即使应用把背景色设成 `alpha = 0`，GDI 也会当成不透明色填满，材质永远透不出来**」——★ **该因果被探针 6 证伪**：

- 实测「亚克力 + `FillRect` 实色清屏 + `BitBlt` 提交」（框架现状，格 F1）**并非**材质被盖死：两区差 7.8（底衬参考差 161.5），颜色是「洋红 + 底衬绿分量」的**混合态**，且**局部方差塌陷到 0.000**（条纹被抹平）。
- 对照格 X1（亚克力 + **不透明白**实色）两区差 **0.00**、纯白 ⇒ **不透明色确实盖死材质**；而 F1 的**洋红实色**却透出混合色。
- ⇒ **真正决定「材质是否可见」的不是「清屏写没写 alpha」，而是提交到重定向表面后该像素的 alpha 状态**；`FillRect` 只写 RGB、后缓冲 alpha 读回恒为 **0**（见 K10），故**清屏未必盖死材质**。

⇒ **K3 的正确表述**：**清屏通道无法表达 alpha，因此应用无法主动控制「留空 vs 填充」**；**材质可见性由提交路径与像素 alpha 共同决定，具体机理待初设第一探针钉死**（见 §4 D6、§6 风险①）。

### K5 ★ 提交方式**不影响**材质（推翻我方初判）——★★ **v1.1 按探针 6 撤回**

**v1.0 原文**：`AlphaBlend` 提交（m0）与 `BitBlt` 提交（m1）**结果几乎一致** ⇒ 真正的开关是**背景像素的 alpha 值**，不是提交函数 ⇒ 不需要分层窗口/DirectComposition。

**★ 探针 6 的受控实测否定了这条结论**（同底衬、同位置、同尺寸，双区差分；重复格 X3 与 F1 读数**逐位相同**（均 7.76）⇒ 非随机；★ `AlphaBlend` 侧存在过渡态噪声，见 K11 的 6 次运行记录）：

| 对比组 | `BitBlt` | `AlphaBlend` | 判读 |
|---|---|---|---|
| 亚克力 + **DIB a=0**（探针 3 的配置） | G2 = 42.9 | G1 = **161.5** | ★ **不一致（差 3.8×）** |
| 亚克力 + **DDB 洋红实色** | F1 = 7.8 | G4 = **30.3** | ★ **不一致（差 3.9×）** |

其中 G1 的方差比 = **1.000**（底衬原样锐利透出 = 裸透），G2 的方差比 = 0.001（材质生效）⇒ **同一个 DIB、同一份像素，仅换提交函数，结果从「材质生效」变成「裸透」**。

⇒ **K5 收窄为**：**「提交方式不影响材质」只在探针 3 的 `WS_POPUP` + 特定目视条件下成立，不能推广到框架形态**。真实结论是：**提交函数与缓冲类型共同决定可见结果**，且 **`AlphaBlend` 提交会把「alpha=0 的背景」变成裸透（而不是材质）** —— 这对 S2 的候选实现是**决定性的**（选错提交函数会直接产出 K4 的最差结果）。

⇒ 分层窗口 / DirectComposition **是否真不需要**，**不能**再以 K5 为依据；改为**初设论证 + 实测**（见 §4 D6）。

### K6 系统圆角会**连材质与自绘内容一起裁**（探针 5 实测）

探针 5（完整复刻框架流程）窗口 A（亚克力 + `DWMWCP_ROUND`）：材质与自绘内容**都被系统圆角裁切**，圆角外为桌面，**无方形材质溢出**。

#### K10 ★ `FillRect` 清屏**不写 alpha**，且 DDB 的 alpha 通道**按 GDI 语义无定义**

| 格 | 缓冲 | 清屏 | 读回 BGRA |
|---|---|---|---|
| F1/F3/G4/X3 | DDB | `FillRect` 洋红 | `(255,0,255,**0**)` |
| G5 | DIB | `FillRect` 洋红 | `(255,0,255,**0**)` |
| G3 | DIB | 写预乘白 0.8 | `(204,204,204,**204**)` |
| F2/F4（跳过清屏） | DDB | 无 | `(0,0,0,0)` |

⇒ 两条事实：① **`FillRect` 不写 alpha 字节**（DIB 上也为 0 —— 这一格 G5 是关键的**缓冲对照**，排除了「DDB alpha 读回不可信」的替代解释）；② **跳过清屏时 DDB 内容为全 0（黑）**，不是「留空」。

★ **方法论纪律**：DDB 的 alpha 通道按 GDI 语义**本就无定义** ⇒ **单看 DDB 的 alpha 读回不能作为「材质会透出」的证据**；判据必须落在**屏幕层对照**（这正是探针 6 做双区差分抓屏的原因）。

#### K11 ★ 提交函数与缓冲类型**共同**决定可见结果（否定 K5，见上）

（事实表见 K5。★ **稳定性与噪声（6 次独立运行实测，如实记录）**：
- **`BitBlt` 侧恒定**：F1 = 7.76 / X3 = 7.76（重复格，逐位相同）/ G2 = 42.94 —— **6/6 次完全一致**；
- ⚠️ **`AlphaBlend` 侧有过渡态**：G1 在 6 次中 5 次读到 **161.52**（方差比 1.000 = 完全裸透），**1 次读到 146.88**（方差比 0.827 = 材质尚未完全稳定）。延长 DWM 静置时间至 1600ms 后复测 5 次，仍见 1 次 157.81（0.947）。
- ⇒ **结论不受影响**：`AlphaBlend` 侧恒在 **146.9–161.5** 区间、`BitBlt` 侧恒 **42.94** ⇒ **两者从不相等，差 ≥3.4×**，「提交函数不影响材质」被稳定否定。
- ⇒ ★★ **但这对 A1（机制验证）是一条硬约束**：**凡以「材质生效」为判据的像素采样，必须先等到合成稳定，且判据要写成区间/相对量，不能写成单次绝对读数** —— 这正是外部评审 P2-2 对像素判据的担忧在**实测层的印证**（本条已并入 §5 A1 与 §6 风险①）。）

#### K13 ★★★ **R-b 的落地条件 = 控件像素必须携带 `alpha = 255`**（2026-10-11 增测，**本轮最重要的可实现性发现**）

★ **发现过程**：探针 6 的抓屏在**控件区**（不是背景区）暴露异常——框架现状 F1（亚克力 + `FillRect` 清屏 + `BitBlt`）里，**本应不透明**的按钮绘制色是 `(80,120,220)`，抓屏却是 **`(117.7,190.8,255)`**；无材质的 F3 则**精确等于** `(80,120,220)`。
