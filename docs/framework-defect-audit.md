## 2. 排期转向（本文件为什么在此时存在）

**用户口径（2026-09-22）**：「先做缺陷修复的优先级更高；desktop 的 demo 本身是为了作为一个**功能使用的实际例子**来完成，那么这其实可以延迟到缺失的功能全部补齐后再做，而非做一个一直要修改的 demo；ModelProbe 作为已经做好的、用来测试功能最后还原，其实已经足以用来测试功能。」

**据此确立的三条**：

1. **优先级**：**框架侧「缺陷修复 / 缺失补齐」> desktop demo**；
2. **理由**：**demo 是「某个功能的用法示范」，不是开发脚手架**——能力未定型时写 demo，每次框架改动都要跟着改一遍 ⇒ **维护两份真相 + 反复返工**；
3. **验证职责已有承担者**：**ModelProbe 是「第一个真实消费者 + 功能回归载体」**（Phase 7.2 起的用例承载 + Phase 10 起独立为 `examples/ModelProbe`），**足以验证新能力**。
   ⇒ **DesktopNest 推迟**到框架缺失补齐之后；`desktopnest-roadmap.md` §5 的 G-2/G-3/G-4 **不驱动当前排期**（其新查缺口见本文件 §5）。

## 3. 分界判据：什么算「该修」的缺陷

不合判据的**一律记入 §4 的「记账不动」清单**——否则"缺陷"会无限膨胀，"该修"失去意义。

**该修（真缺陷）**，命中任一即成立：

| 判据 | 含义 |
|---|---|
| **① 违反既有原则** | 违反已立的设计原则（如「Event 表示已发生的事实、**原始值不归一化**」——**丢信息**是更严重的一种违反） |
| **② 平台有却被中途丢掉** | 信息本已到达平台层，被翻译/封装环节丢弃 ⇒ 不是"框架没做"，而是"做了但漏了" |
| **③ 无替代路径** | 消费者**没有**可接受的降级/绕行方式 |

**记账不动**，命中任一即成立：

| 判据 | 含义 |
|---|---|
| **a 有兜底路径** | 存在可接受的降级（如轮询代替事件通知） |
| **b 无消费者** | 当前无真实调用方（YAGNI 硬约束，skill 条 22） |

## 7. 记账不动清单（含理由与重启条件）

| ID | 项 | 为什么不动（判据） | 重启条件 |
|---|---|---|---|
| **A-1** | `Panel::ContainsPoint()` **恒 false** | **Phase 9.6 有意语义**（Panel 默认透明 = 「隐形布局容器」）；改它动的是**命中语义**，而当前无消费者（b） | 浮层 / 遮罩真实出现且**必须**靠 Panel 当挡板时 ⇒ **届时优先"用裸 `Widget` 或让部件当子"**，而不是改语义 |
| **A-2** | `~Application` 残留活窗口 → **潜在析构序隐患** | 独立记账（`window-ownership.md` §7）；探针 N=1/2/3/5 × O0/-O2 **无可观测异常**（b） | 出现真实现象，或引入「**进程长存 + 窗口反复创建**」的消费者（托盘常驻即此类） |
| **A-3** | `m_running` / `Run`-`Exit` **语义未定义**（初值 `true` ⇒ `Exit()` 在 `Run()` 前调用也生效） | 与 A-2 同一区域（b） | 与 A-2 同批复核 |
| **A-4** | `RenderingBackend::DrawText` 与 Win32 宏冲突（靠防御性 `#undef`） | 有兜底（a）；改名属 breaking ⇒ 归 **v1.0 API 审查** | v1.0 收口前 |
| **A-5** | 光标色未主题化（`Color::Black` 硬编码） | Phase 9 迁移时 YAGNI（b） | 出现深色主题 / 自定义光标色需求 |
| **A-6** | 键盘入口不对称（`OnKeyDown` 走 `Window`；`OnKeyUp`+`CharInput` 直派） | 已回顾**保持现状**（Tab 拦截必需 `Window`）（b） | 全局快捷键需求出现时统一 |
| **A-7** | `ScrollView` 不做列表语义；**无虚拟化**（`roadmap-deferred` #33） | YAGNI；有先例可抄（b） | 见 D-5（列表控件立项时**一并**评估虚拟化） |
| **A-8** | 多窗口焦点语义 / **无应用级活动窗口**（`roadmap-deferred` #6） | 窗口级焦点（`Window::m_focusedWidget`）当前够用（b） | **多窗口消费者出现**（desktop 的多框 / 全局热键） |
| **A-9** | Phase 8.6 抗锯齿遗留人工验收项（A7 性能基线 / A8 三工具链 / A9 目视对比 / A4 抽查） | 功能不阻塞（a） | 用户在 VS / CLion 执行 |
| **A-10** | ★ **`HasModifier(KeyModifier::None)` 恒返回 `true`**（"**全含**"语义 `(m & q) == q` 对 `q = None` **空洞成立**） | ① 与 `KeyEvent::HasModifier` **必须同名同义**（「一个概念只用一个词」）⇒ 改它=**同时改键盘侧语义**；② **无消费者**（全库只经 `IsShiftDown`/`IsCtrlDown`/`IsAltDown` 传具体修饰键）+ **无测试覆盖** ⇒ 该分支**当前不可达**；③ 属**独立 API 语义问题**，**不应夹在 Phase 19**（b）。★ 来源：Phase 19 详设第二轮评审（2026-09-23），**已实测确认**（复刻表达式跑数值实例，三种 `m` 全部 `Has(None)=1`） | 出现**真实消费者**依赖 `HasModifier(None) == false`；或 **v1.0 API 审查**统一修饰键语义时（届时键盘 / 鼠标两侧一并处理） |
