### 1.1 三个口径同时存在（★ 这是本阶段的真问题）

| 口径 | 语义 | 出现处 | 计数 |
|---|---|---|---|

### 1.2 ★ 在案描述与实测不符（如实登记）

`BackendContract.h:84-89` 写的是：

> 「已知偏差（如实记账，不假装已统一）：`GDIBackend` 的多处边转换仍用 `static_cast<LONG>`（向零截断）⇒ 与本节规则**仅在「负的分数边」上相差 1px**……**本批不改 GDI 的这四处**」

实测三处出入：

| 项 | 在案 | 实测 |
|---|---|---|
| 截断点数量 | 「这**四**处」 | **21 处**（8 个函数） |
| `PushClip` 的归属 | 未提及 | 用 **`lround`**，与 `QuantizeEdge` 的 `floor` **也不同口径**（不仅「截断 vs floor」两方） |
| 偏差方向 | 「仅在负的分数边上相差 1px」 | ★ 该结论只对「截断 vs floor」。`lround` 与 `floor` 在**正数的 `frac ≥ 0.5`** 上也差 1px ⇒ **偏差不止负坐标** |

### 1.3 为什么不能「顺手统一」（在案理由，实测支撑）

`ScaleRect` 在**非 100% DPI 下天然产生分数边** ⇒ 改任何一处的取整方向都会**改变每一条负坐标（及部分正坐标）绘制的像素输出**。⇒ 属需要**独立视觉回归**的改动，不属缺陷批。

### 1.4 影响面（实测）

- 生产代码：`GDIBackend.cpp`（21 + 12 处）· `BackendContract.h`（规范本体已就位，**零改动预期**）· `GLRenderer.cpp`（已用 `SnapVertex`，**零改动预期**）
- 契约文档：`BackendContract.h:84-89` 的「已知偏差」段（本阶段完成后须重写）
- 消费侧：**无公共 API 变更**（取整是后端内部实现）
- 测试：取整口径目前**无专项用例**（M17 的可测试性来自 `BackendContract` 纯函数；GDI 侧的像素输出属目视/探针项）

## §4 决策点（含倾向）

### D1 ★ 统一到哪个口径？——**倾向：`floor`（`QuantizeEdge`）为唯一边口径**

| 候选 | 理由 | 风险 |
|---|---|---|
| **A：`floor`（`QuantizeEdge`）** ★倾向 | 已是**规范本体**（`BackendContract.h` 定线）；GL 侧已采用 ⇒ 统一方向与**已有代码一致**，不是新发明；区间语义正确（`[floor(x), floor(x+w))`） | 改变 GDI 现有像素输出（负坐标 + 正数 frac≥0.5 的边） |
| B：`lround` | 与 `PushClip` 现状一致 | 破坏区间语义（`left' + width' != floor(x+w)` 的老问题）；GL 侧需回退 ⇒ **改动面更大** |
| C：只统一「裁剪 vs 绘制」为同口径，不追求三合一 | 改动最小 | 留下两种口径 ⇒ 与 R1 矛盾 |

### D2 尺寸（`width` / `height`）怎么处理？——**倾向：由量化后的两条边相减导出**

`BackendContract.h:77-80` 已给结论：「**边取 `floor`；尺寸由量化后的两条边相减导出，绝不独立取整**」。⇒ 现有多处 `rc.right = rc.left + static_cast<LONG>(rect.width)`（`:597`/`:978`/`:1053`）**正是**该条禁止的写法（独立取整宽度），本阶段应改为 `rc.right = QuantizeEdge(rect.x + rect.width)`。

★ 注意 `:633-634` 已是「`rect.x + rect.width` 后再转」 ⇒ **同一函数内两处不一致**（`:597` vs `:633`），实测确认。

### D3 像素输出变化的回归方式？——**倾向：库外探针 + 目视双轨**

- 自动：`QuantizeEdge` 已是纯函数 ⇒ 真值表用例（正/负/半整数/±0.5 边界）
- 自动：库外探针渲染同一棵树，**逐字节比对改前改后**，把差异**限制在「负分数边」与「正数 frac≥0.5」两类**（差异清单化，不是「看起来一样」）
- 目视：ModelProbe + harness 各跑一轮（用户侧，条 1）

### D4 `PushClip` 是否同步改？——**倾向：改，且这是 R5 的核心**

裁剪区与绘制区若不同口径，会出现「绘制了一个像素但被裁掉」或反之（Phase 26 已有同族教训：`PushClip` 截断 vs 焦点框 `lround` 吸附 ⇒ DPI 缩放下焦点框缺最后一行/列）。⇒ **裁剪与绘制必须同口径**，否则本阶段没有解决真问题。

### D5 动画/AA 分支（`DrawRect` 的 alpha 版 `:50-51`、`WriteRoundedRectPremultiplied`）是否同一口径？

倾向**是**——它们画的是同一类几何。但 `:50-51` 取的是 `width`/`height`（尺寸）⇒ 按 D2 应改为「边相减」。
