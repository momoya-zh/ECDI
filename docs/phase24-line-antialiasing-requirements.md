## 1. 背景与现状事实

### 1.1 动机

框架里**所有斜线的边缘都是硬边锯齿**：`DrawLine` 走 GDI `MoveToEx`/`LineTo`，该 API 本身不做几何抗锯齿。消费者**已存在且目视可见**——CheckBox 选中态的勾（两段斜线）、CaptionBar 关闭按钮的 X——用户 2026-09-23 已目视确认「多选控件的勾是斜线，同样有锯齿」（审计 v1.2 ①）。

Phase 8.6 立项时已把「斜线」定性为**独立议题**并主动划出（D2：斜线「连 alpha 路径都没有，线宽/端帽/合成顺序都要另行设计」），但同时在两层拆分（覆盖度生成 ⇄ 形状装配）下预言：「斜线未来只需**新增第二层装配**、复用同一覆盖度机制即可，不必改动第一层」。**本阶段 = 兑现这个预言**，并顺带把 Phase 19.1 抽出的 `Render/CoverageRaster` 平台无关合成层消费起来。

### 1.3 相关子系统现状（不改变，但决定落点）

| 子系统 | 现状 | 对本阶段的意义 |
|---|---|---|
| `CornerCoverageMask` | 四分之一圆盘 canonical 掩码 + 缓存（键 = 整数半径，诊断阈值 32） | 覆盖度**生成**层的先例形态；线段需**新形状**，不强行复用圆盘 |

| `BlendAlphaSolid` | DrawRect/圆角半透明路径的既有实现 | **不重写不整合**（N7）——本阶段只加线段能力 |

## 2. 需求条目（R1–R6）

### R1：非轴对齐线段获得几何抗锯齿

`DrawLine` 产出的**斜线段**边缘呈现覆盖度渐变，视觉品质与 `DrawRoundedRect` 圆角的 AA **同级**。不新增绘制原语、不改 `DrawLine` 公共签名（`Point, Point, float width, Color` 原样）。

### R2：复用既有两层架构，线段 AA 成为框架共享能力

覆盖度**生成**必须落平台无关的纯几何层（`src/Render/` 同目录、同形态），**像素合成**必须复用 `Render/CoverageRaster` 同族机制；**不得**在 GDI 后端私有代码里另造一套一次性 AA（★ 与 **#44 同源**的边界：「视觉语义属后端私有实现」的账面，本阶段**收敛一块**而非新增一块）。

### R3：受既有后端级 AA 开关管辖

`SetAntiAliasing(false)` 时线段走 legacy 路径，输出与现状**逐位一致**（沿 K10 的开关语义与 `DrawRoundedRect` 的先例）；开关语义本身不变（后端级、主题不参与）。

### R4：零回归护栏

- **轴对齐整数线段**（水平/垂直）：输出与现状逐位一致（AA 路径对其数学恒等，或显式分流到 legacy——由初设实测后定，**判据 = 逐位一致**）；
- 既有 **286** 用例全绿（四工具链）；
- **公共头 92 → 92（0 新增）/ 公共 API +0**（★ 口径沿 Phase 21 评审教训：**头文件数不变 ≠ 契约不变**——本阶段两者恰好都不变，表述必须分开写）；
- 默认主题下的既有控件视觉（除斜线边缘平滑化外）不变。

### R5：折线接缝连续

共端点的两段线（勾在 `CheckBox.cpp:101` 的中点相接、关闭 X 在中心相接）**不得出现接缝伪影**——交点处既不得「重叠加深」（两段各自混合导致交点像素深于两侧），也不得「缺口断开」。具体接缝算法（端帽形状 / 交点合并）**留初设**，本条只冻结**视觉判据**。

### R6：资源与缓存纪律

线段覆盖度的缓存（若缓存）必须**有界受控**（先例 = `CornerMaskCache` 的诊断阈值 `CornerCoverageMask.h:95`）；像素装配**复用** `PatchSurface` 缓冲，**不得**每帧新建/销毁 DIB（先例 = 8.6 对「DIB 缓存池」的处置：单缓冲复用而非分配器）。

## 3. 决策点（D0–D4，含倾向）

| # | 决策 | 倾向 | 理由 / 备选 |
|---|---|---|---|
| **D0** ★★ | **`a < 1` 的线段是否顺带获得与 `DrawRect` 一致的半透明合成？** | ★ **倾向 = 是**（顺带补齐） | AA 覆盖度路径**天然产出预乘像素、天然经 AlphaBlend** ⇒ 补 alpha 是实现的自然副产物，且消除「同为基本原语、alpha 语义不同」的不一致（**K4**）；8.6 D2 当年也把「连 alpha 路径都没有」记为斜线议题的一部分。**备选** = 本阶段只做几何 AA、`a<1` 维持不透明现状（零行为变化，但账面留一条「DrawLine 丢 alpha」的不一致）。★★ **拍板前置条件 = Q1 的盘点**：若现存主题 / 消费方确有 `a<1` 的线，这是**可见行为变化**，必须显式拍板、不得顺带 |
| **D1** | **轴对齐线段走哪条路**——统一覆盖度路径，还是显式分流 legacy | 倾向**以实测定**：覆盖度模型下轴对齐整数线段的覆盖度应恒为 1 ⇒ 若合成输出逐位等于 legacy 则统一（少一条分支）；否则显式分流 | 判据 = **R4 的逐位一致**；8.6 先例：直边整数像素无需 AA（§1.3） |
| **D2** ★ | **线段覆盖度的缓存键设计**——线段几何自由度（两端点 × 宽度）远大于圆角（仅半径）⇒ 直接照抄「按几何键缓存」可能无界 | 倾向**初设重点论证**：按「规范化几何」（长度/角度量化分桶）缓存 vs **逐段直算不缓存**，以 Q4 的每帧调用量实测对比后定 | 缓存先例（CornerMaskCache）的价值在「键空间小」；线段键空间大是**本质差异**，不得无脑照抄（R6 的有界性判据在此落地） |
| **D3** ★ | **端帽语义**——覆盖度模型的端帽（方帽/圆帽/无帽）选哪种，才能既与现状 GDI `PS_SOLID` 的端帽视觉**兼容**、又满足 **R5 接缝连续** | 倾向**先取证再设计**（skill 条 105）：初设先实测 GDI 既有端帽形态（现状视觉基线），再定覆盖度端帽；**不凭推断写期望值** | 这是本阶段**唯一的视觉争议点**；端帽选错会直接违背 R5（两段相接处缺口/鼓包） |
| **D4** | **宽度语义冻结**——本阶段是否把「宽度整数化」升级为亚像素宽度 | ★ **倾向冻结**（宽度仍按现状语义整数化，覆盖度以整数宽度为输入） | 亚像素宽度 = **#46（后端取整口径）** 的相邻议题，混入会让本阶段失焦（8.6 D2 同款教训：一次只解一个议题）；备选 = 顺带升级（**不倾向**） |

## 4. 非目标（YAGNI 圈定）

| # | 不做 | 理由 |
|---|---|---|
| **N1** | **曲线 / 圆弧抗锯齿** | ★ **K12：原语不存在**（variant 全集无 DrawArc）⇒ 无载体；`roadmap-deferred.md` 头部「DrawArc」记账项继续有效 |
| **N2** | **虚线 / 点线（dashed）的 AA** | 焦点框走独立的 `DrawFocusRectCommand`（`PS_DOT`）；「点线 + 覆盖度」的交互是另一个议题（与 **#11 / #44** 相邻）；本阶段的覆盖度底座**不得阻碍**将来扩展，但本身不做 |
| **N3** | **亚像素宽度 / 浮点宽度语义变更** | **D4 冻结**；与 **#46**（`DrawRect` 截断 vs `PushClip`/`DrawLine` 取整）相邻，待独立立项 |
| **N4** | **主题层 AA 配置项** | 8.6 D6 边界继续有效——AA 是**能力层**，开关留在后端级（K10） |
| **N5** | **第二渲染后端 / GPU 路径** | 线段 AA 落平台无关层**正是**为将来后端复用铺路（R2），但本阶段不实现任何第二后端（**#44** 记账不动） |
| **N6** ★ | ★★ **为本阶段新建公共抽象**——`ILineRasterizer` / 公开的 `LineCoverageMask` 公共头之类 | 先例 = **Phase 21 N6**（不得因可测性造公共抽象）：纯几何层放**内部头**（`src/Render/`）已足够无头测试（K10/K11 先例）⇒ **公共面零变更**（R4） |
| **N7** | **重写 / 整合既有 `BlendAlphaSolid` 与圆角 AA 路径** | 本阶段只**加**线段能力 + `DrawLine` 入口分流；既有路径零改动（除 `DrawLine` 自身）。发现的可整合点**如实记账**，不顺手重构 |
