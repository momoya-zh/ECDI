### 1.2 ★★★ 原文未提、且量级更重的一条：折行支**每行一次「整串预备」** ⇒ O(L·N)

Phase 38 把折行接进编辑器后，`TextBox::RecalculateLines` 的折行支走基类引擎（`TextBox.cpp:466`），而引擎的每行适配都**把整串传进去**：

```cpp
// TextWidget.cpp:270 —— 每「视觉行」调一次，text 是整串
const TextFit fit = measurer.FitText(font, text, scan, limit);
```

两个生产测量器在这个入口内部各自做一次 **O(N) 的整串预备**：

| 测量器 | 每行固定成本（与行宽无关） | 行号 |
|---|---|---|
| GDI | `ByteOffsetToCodepointIndex(text, text.size())`（整串数一遍码点，**只为了知道 `totalCp`**） | `GDITextMeasurer.cpp:153` |
| GDI | `CodepointIndexToByteOffset(text, startCp)` + `UTF8ToWide(text.substr(byteStart))` ⇒ **整条尾部拷贝 + 宽字符转换** | `:170-171` |
| FreeType | 同上第一项 `ByteOffsetToCodepointIndex(...)` | `FontEngine.cpp:509` |
| FreeType | `DecodeUtf8(text)` ⇒ **整串解码成 `vector<char32_t>`**（且 `reserve(utf8.size())` 对 CJK 是 **3× 过预留**，`ECDI/src/Render/Utf8Decode.h:20`——★ 该头在 **`src/`** 下（私有头），**不与** `include/ECDI/Render/TextMeasurer.h` 同前缀，v1.0 写成 `Render/Utf8Decode.h` 有歧义） | `FontEngine.cpp:529` |

⇒ 折行 L 行 = **L 次整串解码 / 计数 / 拷贝**。20k 码点（60 KB）的 CJK 串在**约 400 DIP 宽**（14px 字 ≈ 28.6 字/行）下 **L ≈ 700**（20 000 ÷ 28.6）⇒ 仅 `totalCp` 计数一项就是 700 × 14.9 µs ≈ **10.4 ms**，FT 侧再加 700 × 38.7 µs ≈ **27 ms**，并伴随 **700 次 × 240 KB** 的 `vector` 分配/释放（≈ **168 MB** churn）——**每次按键重建都付一遍**。

★ **这是下界，不是估计值**：`GDITextMeasurer.cpp:170-171` 的「尾串 `substr` + `UTF8ToWide`」与 FT 的 `FitText` 逐码点累加都**未计入**（表 3 只测了单项固定成本）；另外 L 随字宽 / 控件宽浮动（26–32 字/行 ⇒ L ∈ 625–770）⇒ 报区间 **10–12 ms（GDI 的 `totalCp` 一项）/ 25–30 ms（FT `DecodeUtf8`）/ 150–185 MB**，**不报单点**。

★★ **但本稿建议：B 不在本 Phase 做**（D39-3）。理由是它的修法要动**测量器接缝**（要么给 `FitText` 加「带游标的增量接口」= 改契约 + 3 个实现 + 测试替身；要么在 measurer 内部按 `(data 指针, size)` 缓存偏移表 = 引入一个「同一个串被反复传入」的隐式假设），风险档与 A 完全不同，混在一起会让「近乎零 API + 可逐位对拍」的 A 失去干净的判据。⇒ **建议新立 #83**（§6），本稿只把读数与机理落档。

### 1.3 现状量化（探针实测，2026-10-29）

**采集方式**：两个独立 TU 的微探针（`probe.cpp` 只链 `Core/UTF8.cpp`，不依赖 Window / 测量器），**不写盘进 CMake、不入库**，命令与 flag 如下；`-O2`、MinGW g++ 16.1、本机 i7 级 20 线程。

```bash
g++ -std=c++20 -O2 -I ECDI/include probe.cpp ECDI/src/Core/UTF8.cpp -o probe.exe
```

**表 1 · 复刻 `RecalculateLines` 非折行支的循环体（每码点 2 次换算 + 1 次 1–4 字节 `substr`）**
取 n 次重复的**最小值**（CJK = 每码点 3 字节的 `字`；ASCII = `a`）：

| 内容 | 码点 | 现状循环 | 单趟推进（候选修法） | 倍率 | 分配次数 |
|---|---|---|---|---|---|
| CJK | 1 000 | **0.641 ms** | 0.0030 ms | 214× | **0** |
| CJK | 5 000 | **15.461 ms** | 0.0140 ms | 1 104× | **0** |
| CJK | 10 000 | **63.130 ms** | 0.0280 ms | 2 255× | **0** |
| CJK | 20 000 | **257.194 ms** | 0.0560 ms | 4 593× | **0** |
| ASCII | 1 000 | 0.342 ms | 0.0010 ms | 342× | **0** |
| ASCII | 5 000 | 9.039 ms | 0.0050 ms | 1 808× | **0** |
| ASCII | 10 000 | 36.320 ms | 0.0100 ms | 3 632× | **0** |
| ASCII | 20 000 | 143.043 ms | 0.0210 ms | 6 812× | **0** |

★ **二次性判读**：CJK 1k→2k…20k 时 0.64 → 15.5 → 63.1 → 257.2 ms；**n 翻倍耗时 ≈ ×4**（5k→10k = 4.08×，10k→20k = 4.07×）⇒ 实测就是 O(N²)，不是「常数大」。

### 1.4 触发面与用户可感知后果

| 场景 | 走的支 | 每次重建代价（20k CJK） |
|---|---|---|
| 日志窗 / JSON 预览（**无折行**、单段落） | 非折行支（A） | **257 ms** ⇒ 按键明显卡顿，输入延迟肉眼可见 |

## §3 范围与非目标

### 范围（R1–R2）

- **R1（主体）** `TextBox::RecalculateLines` 非折行支改**单趟推进**：`byte` 游标按前导字节长推进、同趟累计码点索引；判行尾用**就地解码**（把 `m_text.data() + byte` 与**剩余长度**交给首码点解码，**不切子串**）后比较 `U'\n'`——★ **不是**「只看首字节 == 0x0A」（v1.0 的说法在 overlong 脏输入上与现状分叉，且与折行支分叉，§7-3）；**消灭循环体内的两次偏移换算与一次 `substr`**。要求：行表（`startCp` / `cpCount` / `width` / `ownedEnd` / `totalHeight`）**逐位不变**（**含** A6 的十一类样本）。
- **R2（顺手，零风险）** `TextMeasurer::FitText` 默认体的**纯等价变换**：`:100` 的 `byteStart` 提到二分循环外；首码点切片的换算 **三次并为两次**（★ **不是「并为一次」**：`:86` / `:87` 两处 `CodepointIndexToByteOffset(text, startCp)` 是同一表达式 ⇒ 并一次；`:85` 的 `startCp + 1` **推不出来**——省它需要「序列长」，而 `SequenceLength` 是 `Core/UTF8.cpp:9-15` 匿名 namespace 的内部辅助，公共头 inline 体拿不到，复制前导判定又破坏单源）。仅影响 fallback 路径（生产走覆写），**行为逐位不变**。

### 非目标（N1–N8）

| # | 不做 | 理由 |
|---|---|---|
| **N1** | 折行支每行「整串预备」（§1.2 的 B） | 要动测量器接缝，风险档不同 ⇒ **建议新立 #83**（§6） |
| **N2** | `OnPaint` / `DrawTextContent` 的每行换算 | 与 B 同量级同解；单修一节等于拆半 | 
| **N3** | 给 `Core/UTF8` 加「码点 → 字节」随机访问索引表（`vector<uint32_t>`） | ★ 第二次真实消费者未出现（YAGNI）；R1 根本不需要它（单趟推进天然给出顺序访问） |
| **N4** | `BuildDisplayText()` 的整串拷贝（K11） | 20k 串 ≈ 2 µs，比 A 小 5 个数量级；且改签名会影响 3 个调用点 + 派生类 |

## §7 初设闸门（移交初设的必答项）

1. **单趟推进的逐行骨架**：`byte` / `cp` 双游标的初值与推进式；循环条件为什么可以从 `i < count` 改成 `byte < size`（**迭代数相等的证明见第 3 条 ②**）；`count` 从哪里来（顺带累计 vs 调 `GetCodepointCount()` 一次）。
2. **脏字节的等价性证明（两档，不得混为一谈）**：
   - **长度档**：`SequenceLength`（`Core/UTF8.cpp:9-15`）对非法前导（`10xxxxxx` / `11111xxx`）按 **1 字节**推进 ⇒ 单趟必须**逐字复刻**该规则，否则行表在脏字节上与改前分叉（A6 第六、七类）。
   - **解码档**：`DecodeFirstCodepoint`（`:60-79`）在**剩余长度 < 序列长**时**回退成 `lead`**（既不是跳过、也不是 0）⇒ 单趟必须复刻这一格；★ 它正是 `"A\xC0"` 这类**尾截断**的行表来源（`CodepointIndexToByteOffset` 在此还会**越过 `size`**，靠 `substr` 的计数钳制兜住）。
3. **`\n` 判定的等价性（★ v1.1 重写：v1.0 的「只看首字节」有洞——这是本 Phase 唯一的阻塞项）**
   - **v1.0 的说法**：`0x0A` 不可能出现在多字节序列的续字节位（续字节 ∈ 0x80–0xBF）⇒ 只看首字节即可判 `\n`。**这条只在合法 UTF-8 上成立。**
   - **洞**：现循环**不是**看首字节，而是 `DecodeFirstCodepoint` 解码后比 `cp == U'\n'`（`TextBox.cpp:484-485`）；而该函数（`Core/UTF8.cpp:62-77`）**不拒绝 overlong**：`SequenceLength(0xC0) = 2` ⇒ 解出 `((0xC0 & 0x1F) << 6) | (0x8A & 0x3F)` = **`U+000A`**；`E0 80 8A` / `F0 80 80 8A` 同理；连 `C0 4A`（**续字节低 6 位**恰为 0x0A，与 0x8A 等价）也中。⇒ 现状在这几种脏序列上**会断行**，只认首字节 0x0A 的单趟**不会** ⇒ 与 R1「行表逐位不变」**直接冲突**。
   - **为什么 A6 原来兜不住**：`0xC0` 是**形式合法的 2 字节前导**（`(b & 0xE0) == 0xC0` 成立）⇒ 既不是「非法首字节」（0x80–0xBF / 0xF8–0xFF），也不是「截断续字节」⇒ **原十类样本一类都不覆盖**（v1.1 已补第十一类）。
   - **★ 交叉支证据（v1.1 新增；比「脏输入行为变化」重一档）**：折行支走 `DecodeUtf8`（`ECDI/src/Render/Utf8Decode.h:28-31`），它**同样接受 overlong**（`(b0 >> 5) == 0x6` 不校验最小值）⇒ `BuildTextLayout` 的 `cps[i] == U'\n'`（`TextWidget.cpp:243`——v1.1 首稿误写 `:241`，2026-10-29 复盘时订正）在 overlong 上**也会断行**。⇒ 若非折行支改成只认 0x0A，**同一串在折行 / 非折行两种模式下会得出不同行表**——这比「改了脏输入行为」严重得多，且直接顶撞「测量 / 渲染同一套解码」的同源前提。
   - **出路 (a)（推荐；本稿取此）**：**就地复刻解码语义**——单趟对 `(m_text.data() + byte, m_text.size() - byte)` 解首码点再比较；**零偏移换算、零 `substr`**、每码点 O(1) ⇒ 总 **O(N)**。落点见 **D39-7**（推荐 **A2**：`Core/UTF8.h` 加 `const char*` + `std::size_t` 重载、`std::string` 版转发；**A1 局部复刻会让长度判定与解码双源**）。
   - **出路 (b)（备选；不推荐）**：把「不再对 overlong `\n` 断行」定性为**修复**、接受行为变化（A6 增 overlong 类 + 初设记账）。不推荐的理由即上一条：单改非折行支 = 两口径分叉；要选 (b) 就必须**连 `DecodeUtf8` 一起改**，那是动「测量 / 渲染同一解码」的同源前提，风险档与本 Phase 完全不同 ⇒ 应另立 R，不塞进 R1。
   - **初设必答（三条）**：① 单趟的解码分支与 `Core/UTF8.cpp:60-79` 的**逐行对齐表**（含「剩余长度不足 ⇒ `cp = lead`」）；② `byte += len` **允许越过 `size`**，且 `while (byte < size)` 的**迭代数 == 原 `count`**（需给证明：`ByteOffsetToCodepointIndex(text, size)` 的 `pos` 与单趟 `byte` 同式推进）；③ 若取 A1，必须加「双源一致性」用例（同一批脏字节喂两个实现，结果逐位相同）。
4. **R2 的等价性论证**：`byteStart` 外提后，二分体对 `MeasureText` 的调用序列是否**逐次相同**（A5 的判据基础）。
5. **批 0 基准的采集口径**：A5 的常量表必须在 HEAD 上、**改代码之前**采完（Phase 38 的批 0 先例），并写明「采不到就不得动 R2」。
6. **耗时探针的形态**：是继续用一次性临时探针（命令写进文档），还是落成 `tools/phase39_*_probe.cpp`（要定是否进 CMake）——初设给结论。
7. **★ v1.1 新增 · 公共头改动的编译代价**：A2 要动 `Core/UTF8.h`（K12：几乎全部 TU 重编）⇒ 必须与 R2 **同批编一次**，不得分两轮验；且该头 `:26-29` 的文档注释（「`RecalculateLines` 行扫描 / `GetWordBounds` 分词共用」）要**同步**补上「重载版 = 非折行支单趟扫描用」，别让头注释与新重载脱节。
