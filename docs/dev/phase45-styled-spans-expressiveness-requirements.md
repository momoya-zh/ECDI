### 2.2 为什么选 A（机理）

Phase 44 已把「一串文本按区间拆成多次单 font 调用」的编排层建完（K45-12）：span 表 → `BuildRunsForRange` 逐 run 物化 Font → 逐 run 测宽 → 逐 run 发既有命令。本 Phase 缺的只是**两个维度接线 + 一个行框口径**：斜体 = `Font` 加一个位（GDI 落 LOGFONT 位段、GL 落 `FaceIdFor` 选面——两链消费点都在 `Font` 上，K45-4/K45-5）；字号 = span 覆盖加一个 override 字段（`Font.size` 本就是全部缓存键的既有键维，K45-6——span 面放开 size 后自然流入现有键）；行框 = 从「单值 × 行数」改「逐行 max + 基线共享」（K45-9/K45-11）。零 span 与零新维度覆盖时编排层退化 = 今日路径，红线 1 / C45-2 由此结构性成立。

## §3 核心设计决策（倾向稿；裁决权在用户，见 §6）

### D45-1 · 字段位置与形状（闸门 1 配套）

- **italic 落 `Font`**（+1 字段，默认 `false` = 今日逐位）：GDI 消费点 = LOGFONT 位段（K45-5），GL 消费点 = `FaceIdFor` 选面（K45-4）——两链都在 `Font` 上，span 面只做 override 传递。★ C7560 声明序纪律：新字段**追加结构体末尾**（`Font.h:23` weight 注释明写「声明序：必须位于 family 之后」同族；`FontWeightTests.cpp:78-79` designated 初始化先例面普查入 O45-4）。
- **italic 落 `SpanStyle`**（+1 override，nullopt = 继承基样式）——物化点 = K45-8 单站 `rFont` 组装（+1 分支）。
- **size 只落 `SpanStyle`**（+1 override，`optional<float>`，语义 = **DIP 高度绝对值**，与 `Font.size` 同语义不跨换算）；控件级字号已有 `Font.size` 表达，span 面不重复定义缩放语义。★ 物化同站（+1 分支）；size 流入全部既有缓存键（K45-6 键内已含 size）。
- **`FaceIdFor` 扩参**：`(family, weight, italic = false)`——默认参数保兼容（`FontEngine.h:96` `weight = 400` 先例）；11 处调用点逐处显式传参（GL 渲染链显式、测量链随 `Font` 传）。★ v1.1：**扩参必连带 `familyCache` 键扩 italic 维**（K45-6 第 7 族 / 评审 P0-2——否则斜体首次调用后静默失效），且选面逻辑须拆 **direct / 非 direct 两相**（K45-3：direct 路径今日不排除斜体面，开 italic 后其行为需要定义——闸门 2 前置）。

### D45-2 · 斜体选面政策（闸门 2，勘察后裁）

三候选（O45-1 / O45-2 探针数据到位后用户签字裁）：

- **ⓐ 限真斜体面**：两链一致——请求 italic 且族内无真斜体面 ⇒ **不斜**（按 C36-1 消费边界精神退化）；两链零分歧、判据单相；代价 = CJK 文本的 markdown 斜体可能静默不斜（影响面 = O45-1 实证的「真斜体面普查」读数）。
- **ⓑ GDI 合成斜切 + GL 不合成记已知分歧**：C36-4 同族扩容记录法；消费端中文也有斜体观感；代价 = 两链像素分歧 + 两链判据分相（T45-8 按链分相）。
- **ⓒ GL 也合成**：动栅格化路径 = 破红线 3 ⇒ **默认出局**（除非用户明示收窄红线）。

★ **先探针后定案**（硬纪律）：O45-2 须实测「GDI `lfItalic=TRUE` 在无斜体面族是否真合成斜切 + 宽度增量」与「GL 请求 italic face 时的当前 fallback 行为」两读数后，闸门 2 才具备裁决输入。

### D45-3 · 混字号行框口径（闸门 4 配套，初设钉死后向用户报备）

- **逐行行高 = 该行全部 run 行高 max**（K45-9 五站全改：布局 `:423` 单点取行高 → 逐行取 max；totalHeight = Σ 逐行行高；绘制 `:658/:718/:737` 与 preferred `:824/:829` 随行框口径走）。
- **行内共享一条基线**：run y = baseline − run ascent（排版标准式）；两链同口径（C45-4）。
- **联动面**：`CalculateTextPosition` 垂直居中（`TextWidget.cpp:632-637` 用单值行高）改按首行/行框口径；只读 `TextBox` 选区 rect 高随行框；空行占高 = 行内无 run ⇒ 沿基字体行高（D29-Ⅴ 口径不破）。
- ★ K45-13 是本决策的前置缺口：GDI 链 per-run ascent 无公共物 ⇒ 闸门 5（接口 +1 与否）。
- ★ GL `:254` 的 `floor(pos.y) + floor(Ascent)` 与 emit 侧非整数 y 的取整交互 = 初设数值细节（Phase 27 floor 吸附先例，O45-3 实测）。
- ★★ **TextBox 固定行高契约冲突（v1.1 吸收评审 P0-3）**：`TextBox.cpp:587` 注释自述「全系统唯一行高来源（8.5.2 固定行高契约——**不支持逐行字体**，Y/lineH 成立）」（逐字亲核）；`GetLineHeight`（`:586`）全文件 **13 处文本命中 = 1 定义 + 7 调用（`:612` / `:628` / `:645` / `:790` / `:813` / `:878` / `:1471`——全列无遗）+ 5 注释（`:163` / `:783` / `:811` / `:908` / `:1403`）**（v1.2 按评审 P2-2 拆口径，撤「…」歧义）+ `lineH` 局部向选区 / 光标 / 滚动 / 行号映射的下游传播。「逐行行高 max」与该契约**正面冲突** ⇒ 处置三候选（ⓐ 只读 `TextBox` 维持固定行高 = 全文最大字号行高 / ⓑ 逐行化并全量盘点 13+ 消费点 / ⓒ 混字号场景限定不进 `TextBox`）= **O45-3 勘察 + 闸门 4 前置**；§4.1 `TextBox` 预算改「勘察后估」。
- ★★ **totalHeight 浮点等价守卫（v1.1 吸收评审 P0-4）**：float32 **乘法与逐行累加舍入路径不同**——本稿以 `Math.fround` 复核：`lh=19.2, n=6` ⇒ mul `115.20000457763672` vs sum `115.19999694824219`；`13.8×10` / `21.333×10` 同样不等（★ 复核订正评审一处：`18.6×3` 恰相等）；随机 20 万组 **52.4% 不等**（评审实测 ≈49.6%，同量级）⇒ **全部行同高 ⇒ 沿用 `lineHeight × 行数` 原式**（零 span 相与 C45-2 相结构性走原式 = 红线 1 不破）；**存在异高行才 Σ 累加**（仅新维度激活可达）。

### D45-4 · L44-9 处置与 L44-6 订正

混字号落地基线对齐后，Phase 44 的「跨族混排顶边对齐、接受 7px 行内基线偏置」降级**被取代**：同族基线严格重合结论保留，跨族从「顶边对齐」升级为「基线对齐」⇒ **L44-9 结账条件 = 本期基线对齐落地**。★ 订正：v2.91 称 L44-6「harness 书面确认」，harness 仓实测零记录（§1.2）⇒ 该签署状态不成立、随 L44-9 一并结转、无需补签（新口径的消费者确认走 §5.4 验收映射，由 harness 消费期出证据）。

### D45-5 · 范围边界

落 `TextWidget` 基类 + 只读 `TextBox`（沿 Phase 44 闸门 4-① 已收接入面，**零新增接入工程**）；编辑器通路 × 两新维度仍归 **L44-1**（范围注记扩容，不另立条）；行内 code 背景底片（L44-3）/ 下划线删除线（L44-4）维持不动。

### D45-6 · 兼容契约（默认值 = 今日行为）

`Font.italic = false` ⇒ LOGFONT 位段零变化（K45-5 现状逐位）+ `FaceIdFor` 行为不变（`false` 短路 K45-3 排除点原语义）；`SpanStyle.italic / size = nullopt` ⇒ `rFont` 组装零新分支（K45-8）。⇒ 「Phase 44 spans（weight / family / color）路径逐位不变」**可测**（T45-5），红线 1 结构性成立。
