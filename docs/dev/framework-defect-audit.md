## 2. 排期转向（本文件为什么在此时存在）

**用户口径（2026-09-22）**：「先做缺陷修复的优先级更高；desktop 的 demo 本身是为了作为一个**功能使用的实际例子**来完成，那么这其实可以延迟到缺失的功能全部补齐后再做，而非做一个一直要修改的 demo；ModelProbe 作为已经做好的、用来测试功能最后还原，其实已经足以用来测试功能。」

**据此确立的三条**：

1. **优先级**：**框架侧「缺陷修复 / 缺失补齐」> desktop demo**；
2. **理由**：**demo 是「某个功能的用法示范」，不是开发脚手架**——能力未定型时写 demo，每次框架改动都要跟着改一遍 ⇒ **维护两份真相 + 反复返工**；
3. **验证职责已有承担者**：**ModelProbe 是「第一个真实消费者 + 功能回归载体」**（Phase 7.2 起的用例承载 + Phase 10 起独立为 `examples/ModelProbe`），**足以验证新能力**。
   ⇒ **DesktopNest 推迟**到框架缺失补齐之后；`desktopnest-roadmap.md` §5 的 G-2/G-3/G-4 **不驱动当前排期**（其新查缺口见本文件 §5）。

## 3. 分界判据：什么算「该修」的缺陷

不合判据的**一律记入 §4 的「记账不动」清单**——否则"缺陷"会无限膨胀，"该修"失去意义。

**该修（真缺陷）**，命中任一即成立：

| 判据 | 含义 |
|---|---|
| **① 违反既有原则** | 违反已立的设计原则（如「Event 表示已发生的事实、**原始值不归一化**」——**丢信息**是更严重的一种违反） |
| **② 平台有却被中途丢掉** | 信息本已到达平台层，被翻译/封装环节丢弃 ⇒ 不是"框架没做"，而是"做了但漏了" |
| **③ 无替代路径** | 消费者**没有**可接受的降级/绕行方式 |

**记账不动**，命中任一即成立：

| 判据 | 含义 |
|---|---|
| **a 有兜底路径** | 存在可接受的降级（如轮询代替事件通知） |
| **b 无消费者** | 当前无真实调用方（YAGNI 硬约束，skill 条 22） |

## 4. 缺陷清单（该修 / 该补）

| ID | 项 | 证据 / 根因摘要 | 类型 | 命中判据 | 闭环状态 |
|---|---|---|---|---|---|
| **D-1** | `MouseEvent` 家族只带坐标、`wParam` 按键位与修饰键被丢弃 | `MouseEvent.h` 仅 `m_mouseX/Y`；滚动条与文本框被迫各自维护状态 | 契约缺失 | ①② | ✅ **Phase 19** |
| **D-2** | 进程为系统级 DPI 感知且缺屏幕/DPI 查询 API | 系统虚拟化致 `dpi` 恒为 96，非 96 DPI 缩放失真 | 真缺陷 | ③ | ✅ **Phase 20 / 20.1** |
| **D-3** | 运行时 `HICON` → `Image` 通路缺失（`desktopnest` G-2） | WIC 仅支持 `.ico` 文件，缺运行时句柄转换（内核/外壳可分离无头测试） | 缺失能力 | 补齐接口 | ✅ **Phase 21** |
| **D-4** | 无「工作线程 → UI 线程」投递机制（`desktopnest` G-3） | 仅见内部 `PostMessageW` 唤醒，缺应用级通用异步派发 | 缺失能力 | 异步解耦 | ✅ **Phase 23** |
| **D-5** | 无列表 / 网格容器（`desktopnest` G-7） | `ScrollView` 不推导条目布局，ModelProbe 曾手写行池 | 缺失能力 | 第二消费者触发 | ✅ **Phase 25** |
| **D-6** | 抗锯齿只覆盖圆角（`DrawLine` 为硬边） | `CheckBox` 勾等斜线无覆盖度栅格化通道（`DrawPolyline` 另计 `#48`） | 缺失能力 | 可见消费者 | ✅ **Phase 24** |
| **D-7** | `Create` 的 DIP 尺寸契约在 `Create` → `Show()` 之间不成立 | Phase 20 为避构造期 `WM_SIZE` 崩溃将换算延至 `Show()` | 契约错误 | ①③ | ✅ **Phase 22** |
| **D-8** | 文本度量基准与渲染基准不一致 | `GDITextMeasurer` 读屏幕 DC 而 `GDIBackend` 读窗口 DPI | 契约错误 | ①② | ✅ **Phase 26** |

## 5. desktop 侧缺口（与框架缺陷分栏记）

- **G-1 / G-2 / G-3 / G-4 / G-7**：分别随 **Phase 16 / Phase 21 / Phase 23 / Phase 20+20.1 / Phase 25** 全部闭环。
- **G-5（窗口内浮层 / 菜单机制）**：原记应用侧可用 z 序与捕获自绘；随真实多消费者出现，已于 **Phase 42（`#81`）** 落地框架级 `m_overlayRoot` 三层栈与 Light Dismiss。
- **G-6（应用内控件级 drag/drop）**：文件拖入（`WM_DROPFILES`）已由 Phase 14 提供；控件级通用拖拽视业务消费出现再定。
- **未验项**：多窗口 `WindowLayer::Desktop`（10+ 窗口下前景 hook 成本与重插序）待实际多窗需求出现时压测。

## 7. 记账不动清单（含理由与重启条件）

| ID | 项 | 为什么不动（判据） | 重启条件 |
|---|---|---|---|
| **A-1** | `Panel::ContainsPoint()` 恒 false | Phase 9.6 有意语义（Panel 默认透明 = 隐形布局容器）；改之影响命中契约（b） | 若确需容器级遮挡，优先使用裸 `Widget` 或专门浮层面板。 |
| **A-2** | `~Application` 残留活窗口析构序隐患 | ✅ **已于 2026-10-12 修复关闭（`#57` / ca612eb）**：加 `m_shuttingDown` + 显式清空容器 + `OnWindowDestroyed` 早退。 | 已闭环（仅作历史留档）。 |
| **A-3** | `m_running` / `Run`-`Exit` 语义未定义 | 初值 `true` 致 `Exit()` 在 `Run()` 前亦生效（b） | 随 Application 生命周期整理审查。 |
| **A-4** | `RenderingBackend::DrawText` 与 Win32 宏冲突 | 现以防御性 `#undef` 兜底（a）；改名属 breaking 变更 | **v1.0 API 审查**前统一改名。 |
| **A-5** | 光标色未主题化（`Color::Black` 硬编码） | ✅ **已于 2026-10-07 修复关闭（Phase 30 / `#51`）**：新增 `TextBoxStyle::caretColor`（默认 Black 零回归）。 | 已闭环。 |
| **A-6** | 键盘入口不对称（3 入口） | 已回顾保持现状（Tab 拦截必需 `Window`）（b） | 全局快捷键需求出现时统一。 |
| **A-7** | `ScrollView` 无数据虚拟化（`roadmap-deferred` `#33`） | YAGNI；大列表当前由 `ListLayout` 承接（b） | 出现真大数据量性能瓶颈时再评。 |
| **A-8** | 多窗口焦点 / 无应用级活动窗口（`#6`） | 窗口级焦点当前够用（b） | 多窗口协同或全局热键消费者出现时。 |
| **A-9** | Phase 8.6 抗锯齿遗留人工验收项（A7/A8/A9/A4） | 功能不阻塞（a） | 用户侧人工抽检对比。 |
| **A-10** | `HasModifier(KeyModifier::None)` 恒返回 `true` | 与 `KeyEvent` 同名同义且无消费者直接传 `None`（b） | 出现真实依赖 `HasModifier(None)==false` 的消费者或 v1.0 修饰键审查。 |
