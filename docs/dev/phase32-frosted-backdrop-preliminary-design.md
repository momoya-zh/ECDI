### 2.3 五问作答

- **Q1（机理·加性泄漏定律）**：**A=0 的像素在亚克力合成中以「RGB 逐通道叠加」参与**——M1 的屏幕均值漂移 = 写入 RGB 本身（本格因 DWORD 组装笔误实际写入 RGB(43,47,56) 而非意图的 (56,47,43)，**漂移读数与实际写入字节逐通道精确吻合**——无自由参数的更硬证据）；材质图案完好（deltaAB/方差比与 M0 逐位一致）。**该定律一次性解释探针 6 的 F1（洋红 RGB 泄漏 = MIXED 观感）、F2（黑 = 零贡献 = FROSTED）、X1（不透明白 A=255 = 盖死）与 K11（提交函数差异的本质 = 是否保留缓冲 alpha 到重定向表面）**。
- **Q2（哨兵修补·文字）**：填充矩形级 A=255 + 文字哨兵扫描的混合机制，在真实 DWM 合成下产出「**字形精确（682 px ±8 内）+ 字缝透材质（哨兵残留 0）+ 背景 FROSTED**」三同时。
- **Q3（完整管线）**：Z1 = 填充 + 两种文字混合场景全过；AA 文字边缘目视无恶性黑边（`probe7_after.bmp`，详设给量化判据）。
- **Q4（通道序）**：`0xFF0000FF`→红、`0xFFFF0000`→蓝 ⇒ **`nColor` = AABBGGRR**（COLORREF 布局 + 高位 alpha）。T5 关闭。
- **Q5（降级路径文字）**：白 204 预乘 + 哨兵(204,204,204) + AlphaBlend ⇒ 文字精确 + 控件精确 + 背景真半透——**降级路径不是「纯背景」路径，同样需要 alpha 修补**（这是 P4 没有覆盖的另一半，本轮补上）。

## §3 决策 D32-A..J（逐题裁决）

### D32-A API 语义归属（D1+D5）——**定案：② 新增正交 API，不动 Phase 18 红线**

- 候选①（`SetBackgroundColor` 的 `alpha==0` ⇒ 跳过清屏）**被 Phase 18 红线 ④ 直接禁止**（`background.a` 不得接入任何分支，`phase18-window-background-detailed-design.md` §4.2 红线表；含「`a==0` 跳清屏」的明文反例）。选①必须正式修订 Phase 18 的 C4/A4 契约——成本与风险（牵动 Phase 18 全部既有验收）显著高于新增 API。
- **定案**：新增 `Window::SetWindowBackdrop(BackdropMode mode, const Color& tint)`（配置期）+ `Window::GetWindowBackdropState()`（查询）。**一个概念一个词（条 95①）**：backdrop（衬底材质）≠ background color（底色）。
- **冲突规则（D5 的「谁赢」）**：`mode ≠ None` 时**清屏语义归 backdrop**（清屏 RGB/alpha 由 D32-F 的路径语义决定，`tint` 参数是唯一权威来源）；`Window::SetBackgroundColor` **仅保留 None 模式的既有语义**（该模式下行为逐位同 Phase 18）。同帧两者的优先级由此一条规则钉死，无第二解释。

### D32-B 枚举取值域（D2）——**定案：单枚举 `BackdropMode { None, Acrylic, Degraded }`**

- 依据「取值域须以实测可用性为准」（需求 §4 D2）：`DWMWA_SYSTEMBACKDROP_TYPE` 本机不生效（探针 1）、`ACCENT_ENABLE_BLURBEHIND(3)` 出不了可见白雾（探针 6 格 D2）⇒ **不收 `Mica` / `Blur`**——枚举里放实测不可用的值 = 死值（YAGNI，条 22）。
- `Degraded` **只允许作为 actual 出现**：作为请求传入 ⇒ 记 Warning 并忽略（同 `SetChromeMode` 生命周期的既有惯例，`Window.h:112-113`）。
- 未来取值扩展 = 纯增量（新枚举值 + 新分支），不破坏既有二进制。

### D32-C 请求 vs 实际状态（D3/A7）——**定案：请求态持久 + 实际态 = 最近一次应用结果**

- API：`struct WindowBackdropState { BackdropMode requested; BackdropMode actual; }`，`GetWindowBackdropState() const noexcept` O(1) 读取。
- 生命周期（需求 §5 A7 的四条落 API）：① 请求态 = 应用配置的持久意图（`SetWindowBackdrop` 写入）；② 实际态 = **最近一次应用的结果**（`Show()` 时首次产生；此后每次重应用更新），**不是**对未来行为的保证；③ 平台窗体重建 / 重应用时**不得**残留上一 HWND 的成功读数（实际态归属当前 HWND）；④ 重应用失败 ⇒ 实际态翻转为 `Degraded`，查询立即可见。
- 重应用触发：**初设范围 = `Show()` + `WM_DPICHANGED`**（A8 的自动化部分）；其余触发（主题变更/跨屏/还原）移交详设枚举（§8）。
- ★ **v1.1 补（外部评审 P2）**：① **「尚未应用」查询语义 = 详设必答**——`Show()` 前 `actual` 返回什么（返回 `None` 会被误读为「应用失败」；返回 requested 又与「首次应用于 Show」矛盾）⇒ 详设钉死（候选：轻量 applied 标记 / 第三态；**不强制新增公共枚举值**）；② `Degraded` 作为请求 = **完全忽略且不改变既有请求态**（「忽略」语义钉死）。

### D32-D tint 通道序（D4/T5）——**定案：`nColor` = AABBGGRR**

- 探针 7 R1/R2 实测（§2.2）。框架内唯一转换点：`Color{r,g,b,a} → nColor = (a8<<24) | (b8<<16) | (g8<<8) | r8`（`ToByte` Clamp 沿决策 21/23）。纯红/纯蓝定点实测已做，后续不再依赖歧义值。

### D32-E 缓冲区方案——**定案：GDIBackend 后缓冲 DDB → 32bpp top-down DIB section（全窗口统一切换）**

- 证据：**O1 位等同**（切换对普通窗口可见输出零影响——A6 的缓冲面前提）+ **O2 成本 0.93×**（无代价）。
- 为什么统一而非「仅衬底窗口用 DIB」：双形态意味着 `EnsureBackBuffer` / 所有绘制路径 / 提交路径都要带分支，复杂度与回归面更大；统一后「衬底」退化为「多写 alpha 字节 + 提交函数按模式分支」两件事。
- `EnsureBackBuffer` 改 `CreateDIBSection`（32bpp、`BI_RGB`、负高 top-down ⇒ `dibBits` 行序与 y 向下坐标一致），**尺寸自检重建逻辑逐字保留**（决策 15/26/38——A8 的尺寸交互点不动）。
- 普通窗口（`mode == None`）路径：清屏/绘制/`BitBlt` 全不变（alpha 字节内容对 DWM 不透明合成无意义）⇒ A6①「逐位同 Phase 18」由 O1 + T32 位等同用例双重锚定。

### D32-F ★★ S2 像素生成机制（核心设计问题）——**定案：每命令 typed alpha 修补**

| 内容种类 | 修补方式 | 依据 |
|---|---|---|
| **实心矩形**（`DrawRect`，无 AA） | **矩形级 A=255**——全命令集中唯一的「外接矩形 = 覆盖域」命令 | Z1 按钮/标题栏误差 0.00 |
| **圆角矩形 / AA 覆盖度路径**（`DrawRoundedRect`） | ★ **v1.1 修订（外部评审 P1-1）**：**外接矩形 ≠ 覆盖域**——矩形级修补会把圆角外像素写成不透明（方角盖住材质）⇒ **禁止**。角部/边缘按**覆盖率**处理，两个候选语义由详设探针裁决：**(a)** 不透明混合（现 RGB 已是 cov 混合终值 ⇒ A=255，边缘 = 对背景色混合）；**(b)** 预乘 alpha（RGB=color×cov、A=255×cov ⇒ 材质按比例透过角部——合成更正确，需改写 RGB 而非只写 alpha）。基础设施现成 = Phase 24 `CornerCoverageMask` / `FillPatchFromMask` | 探针 7 未覆盖圆角 ⇒ 详设必补探针 |
| **图像**（`DrawImageCommand`——★ v1.1 勘察：命令在集，`RenderCommand.h:58`） | **保留源 alpha 语义，禁止矩形级修补**——透明 / 半透明 / 不透明像素必须分别验证；执行端形态详设勘察 | 外部评审 P1-1 |
| **部分覆盖类**（`DrawText` / `DrawLine`） | 命令矩形 ∩ 当前裁剪内**哨兵扫描**（`A==0 且 RGB ≠ 哨兵 ⇒ A=255`） | Z1/T2 文字精确 682 + 字缝透材质 |
| **部分覆盖类**（`DrawText` / `DrawLine` 等） | **命令矩形 ∩ 当前裁剪内哨兵扫描**：`A==0 且 RGB ≠ 哨兵 ⇒ A=255` | Z1/T2 文字精确 682 + 字缝透材质（残留 0） |
| **清屏**（路径语义） | None = 既有不透明清屏（不变）；Acrylic = **tint RGB + A=0**；Degraded = **预乘白 204** | M0（黑=零贡献）/ M1（tint 泄漏=正确观感）/ P4·P5 |
| **DWM tint** | `nColor` 的 **RGB 分量固定为黑**（alpha 分量照常）——tint 观感由缓冲泄漏承担 | M1 定律：DWM tint RGB + 缓冲 tint 泄漏 = 双重 tint；二选一，选缓冲侧（AA 混合目标才与视觉背景一致） |
| ~~**DWM tint**~~ | ~~`nColor` 的 RGB 分量固定为黑~~ | ⚠️ **【2026-10-14 事后注记 · C32-12 已修订】** 本行是 **v1.0/v1.1 时点的原始决策**，保留作历史记录；**现行契约 = `nColor` RGB 必须携带 tint**（通道序 `AABBGGRR`）。修订依据见 `phase32-frosted-backdrop-detailed-design.md` §10.5 / C32-12 行：实测「RGB=黑」并非中性，而是 **60% 黑 tint**，会把材质压成单色（跨区差 3.88 vs 45.68）；且 RGB=tint 与 probe8 已知良好参照 `EMP` 格最大偏差仅 **7.6/255** ⇒ **不存在叠加**，「防双重 tint」的担忧不成立。★ **教训**：M1「加性泄漏定律」本身没错（A=0 像素 RGB 逐通道叠加），错在从它推出「DWM tint RGB 必须为黑」——定律描述的是**合成行为**，而「设 0 即中性」是**未经实测的推断**（RGB=0 在 acrylic 下是一个真实的 60% 黑 tint，不是「不设」）。 |

- ★ **v1.1 原则句（外部评审 P1-1）**：「命令有矩形边界」≠「矩形内每像素都应不透明」——修补方式必须跟随**像素级覆盖事实**，而非命令的几何包络。
- **清屏选 tint RGB 而非黑的推论链**：M1 证明 tint-RGB A=0 的泄漏 = 恰好把 DWM tint 的观感搬进缓冲；同时文字 AA 的混合目标 = 清屏 RGB = 视觉背景色 ⇒ AA 边缘观感正确（Z1 目视无恶性黑边）；且哨兵判别对黑内容天然成立（黑 ≠ tint）。
- **哨兵碰撞 = 已知限制（v1.1 按外部评审 P1-3 升格措辞）**：内容像素 RGB 恰等于清屏 tint ⇒ 该像素留在 A=0（材质透过）。★ **「主色错开」只降概率、不消除碰撞**——文字主色与 tint 不同时，**AA 边缘经混色与量化后仍可能恰好等于 tint**。处置：① 作为**已知限制**写入 API 契约（非仅配置建议）；② AA 边缘制定**可重复的验收判据**（详设）；③ 若实测出现缺口，**优先评估用既有覆盖度光栅化结果修补**（Phase 24 `CornerCoverageMask` 先例），而非默认「全帧扫描更正确」。
- **被排除的候选**：整帧统一补 255（杀掉背景留空——K4 最差结果的镜像）/ 整帧保留 0（控件被冲淡——K13 实测 47.8）/ 每帧全表面哨兵扫描（正确但成本与黑哨兵碰撞面大——O2′ 显示成本可接受，留作 per-command 的后备实现，详设二选一收口）。
- **修补的裁剪一致性（盯防项）**：修补矩形 = 命令矩形 ∩ 当前裁剪栈顶——与命令执行同裁剪，防「修补越权」。

### D32-G 提交路径（S3 确认点①③）——**定案：同一 DIB 缓冲，EndFrame 按模式分支提交函数**

- `None` / `Acrylic` ⇒ `BitBlt(SRCCOPY)`（P1/O1：逐字节提交，缓冲 alpha 原样到达重定向表面）；`Degraded` ⇒ `AlphaBlend(AC_SRC_OVER, 0, 255, AC_SRC_ALPHA)`（P4/P5：预乘源 + 保留 alpha 语义）。
- **无第二缓冲**：Acrylic 与 Degraded 共用同一 32bpp DIB（S3 确认点①关闭）；预乘约定 = 仅 Degraded 路径的清屏以预乘形式写入（白 204 = 255×0.8），内容像素为「混合终值」语义（P5 文字精确，确认点③关闭）。
- ★ **v1.1（外部评审 P1-2）**：P5 是**已验证的一组场景**（实色填充 / 文字 / 控件），**非「全部绘制命令均已验证」**——详设必须补「降级 × 内容类型」矩阵：源像素的 `AC_SRC_ALPHA` 预乘一致性、清屏 / GDI / 修补的颜色语义一致、背景边缘不被烘焙成不透明、模式切换首帧无旧 alpha 残留（最后一项由 T32-7 承接）。

### D32-H 状态机与降级链（S3 确认点④）——**定案：单一下降路径 + 可注入失败**

- 应用序列：`Show()` ⇒ 动态解析 `SetWindowCompositionAttribute`（**全仓首个 GetProcAddress**——既有注释明示此前无先例，`Win32PlatformApplication.cpp:239`；失败容忍同 Phase 12 R6 姿态：解析失败/调用失败 ⇒ 仅日志 + 进入降级，不中断）⇒ 成功 ⇒ `actual = Acrylic`；任何失败 ⇒ **立即切换 Degraded 提交语义（白 204）**，`actual = Degraded`。
- **三条失败路径（API 缺失 / 调用失败 / 系统不支持）同归这一条 Degraded 路径**（确认点④关闭；A9① 的注入判据落在「解析函数指针可被测试替换」的接缝上，形态详设钉）。
- 跨帧残留（确认点②）：框架 = 完整重绘模型（决策 29 全量 `BitBlt`）+ 每帧从清屏开始 ⇒ 模式切换时无上一帧语义残留；`EnsureBackBuffer` 重建后新 DIB 首帧即被清屏覆盖——T32 加一条「模式切换后首帧」用例钉住。

### D32-I 系统圆角协同（S5）——**定案：零新机制**

`ApplyDwmEnhancements` 的 `DWMWCP_ROUND` 与 accent 独立并存（探针 5/6 已证共存）；本 Phase 不新增圆角代码，A4 验收在探针 E2E 里带圆角窗口复核。

### D32-J GL 留位（S6/A9②）——**定案：结构性约束三条**

① 新公共 API 全部落在 `Window` 层（平台无关的枚举 + Color）；② `PlatformWindow` 新虚函数**带默认实现**（第二平台可实现，非 Win32 专属形态）；③ GDIBackend 的 alpha 机制 = 后端私有实现（`RenderingBackend` 新增虚函数同样带默认实现），`GLRenderer` 零改动零知晓——A9② 的 grep 结构性判据照 Phase 18 A4 形态在详设落机检。

## §6 契约 C32-1..8

1. **C32-1** `background.a` 仍不得接入任何分支（Phase 18 红线 ④ 原样有效——衬底语义走独立通道）。
2. **C32-2** `mode ≠ None` ⇒ 清屏语义归 backdrop（D32-A 冲突规则唯一条款）。
3. **C32-3** 修补矩形 = 命令矩形 ∩ 当前裁剪栈顶（不越权）。
4. **C32-4** Acrylic 清屏 = `(tintRGB, 0)`；Degraded 清屏 = 预乘白 204；None 清屏逐位同 Phase 18。
5. **C32-5** `nColor` 组装 = `(a<<24)|(b<<16)|(g<<8)|r`，唯一转换点在 Win32PlatformWindow（D32-D）。
6. **C32-6** 实际态归属当前 HWND，重建/重应用即刷新（D32-C③）。
7. **C32-7** 失败路径（解析失败/调用失败/系统不支持）同归 Degraded，可注入、可重复（D32-H）。
8. **C32-8** 新虚函数一律带默认实现（S7：7 零改动红线）。
